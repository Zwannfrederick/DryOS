# DRY OS — Linux & Windows Architectural Gap Analysis (`LINUX_WINDOWS_GAP_ANALYSIS.md`)

**Branch:** `ascension-8.0`  
**Core Comparison Principle:** DRY OS is a capability-isolated `#![no_std]` Rust microkernel (`dry-kernel`) paired with Ring-3 driver/service compartments (`dry-init`, `dry-broker`, `dry-usb`, `dry-blk`, `dry-nvme`, `dry-gpu`, `dry-vfs`). It is NOT POSIX/ABI-compatible with monolithic Linux (`.ko`) or Windows (WDM/WDF `.sys`) kernel modules.

## 2. Structural Compatibility Bottlenecks

1. **Monolithic In-Kernel Assumption (`400–600+` Linux / WDM APIs):** Drivers such as `i915`/`xe`, `nvidia.ko`, and `iwlwifi` assume shared kernel virtual memory, `workqueue` kernel threads, RCU grace periods, `struct page` frame descriptors, `acpi_evaluate_object`, and sysfs/debugfs VFS trees. Emulating hundreds of fake symbols in Ring 0 or a C shim increases attack surface and maintenance debt unacceptably.
2. **No Virtualization / VFIO Pass-Through Layer Yet (`VT-x` + `VT-d IR`):** For complex vendor binaries or Linux DRM/CUDA stacks (`nvidia-open` + `ucodes_ga10x.bin`), the safe architectural boundary on a microkernel is a lightweight VMM/MicroVM (`Approach C`) rather than extending Ring 0 or Ring-3 C shims. `dry-kernel` detects `CPUID.1:ECX[5]` (`VMX`), `DMAR`, and `VT-d` status, but neither hypervisor VMCS management nor `VT-d` Interrupt Remapping is implemented yet.
3. **MUX-less Laptop Topology (`eDP-1` Wired to iGPU):** On the Lenovo IdeaPad Gaming 3 15IHU6 (`82K1`), the internal `1920x1080 @ 165 Hz` eDP panel is wired to Intel `8086:9a49`, while NVIDIA `10de:25a0` is a muxless 3D Controller (`0x030200`). Passing `8086:9a49` to a guest MicroVM would black out the laptop panel; therefore iGPU scanout must remain native (or UEFI GOP fallback), while discrete GPU compute/render must cross explicit read-only surface leases.

## 3. Practical Design Direction Confirmed by Ascension 8.0

- **Simple/medium single-function devices** (`virtio-rng`, `bochs-drm`, `8139cp`, PS/2, xHCI Boot HID/MSC, future I2C-HID touchpad or Intel eDP page-flipper): belong in **`dry-driver-sdk` Native Rust Islands** or bounded **`libdry-lx-compat` C Islands** under `Device Broker` (`dry-broker`).
- **Complex firmware/shader/compute subsystems** (`10de:25a0` NVIDIA OpenRM + GSP + CUDA, full 3D Vulkan/OpenGL): belong behind **MicroVM / VFIO isolation** once hypervisor, `VT-d IR`, and `SHM`/`vsock` compositor offload exist — never inside `kernel/src/`.
- **Default validation safety invariant:** When any required prerequisite or IOMMU boundary is absent, DRY OS **fails closed** (`BLOCKED` / `SKIP`), preserves UEFI GOP display and read-only storage safety, and never guesses hardware behavior.
